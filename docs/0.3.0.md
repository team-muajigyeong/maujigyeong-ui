# 공통 UI 3차 분리 — 2026-09-16

## 범위와 호환성

UI 0.3.0에 AOSTextField와 Switch를 추가한다. 총 아홉 개 컴포넌트를
독립 UI 저장소에서 관리하고, 앱은 고정된 GitHub 커밋을 설치한다.
기존 CSS, JSX 구조, 상태 처리, 이벤트 순서, 주석을 유지했다.
앱에서는 import만 변경한다. 새 공개 타입과 사용 설명은 JSDoc으로 제공한다.

| 경로 | 공개 API | 용도 |
| --- | --- | --- |
| @muajigyeong/ui/text-field | AOSTextField, AOSTextFieldProps | 떠 있는 라벨, 아이콘, 비밀번호 표시 전환 |
| @muajigyeong/ui/switch | default Switch, SwitchProps | 켜기·끄기 설정 |

기존 ControlledInput은 단순 입력 및 textarea 용도로 유지한다.
AOSTextField와 억지로 통합하지 않으며, 이번 작업에서 입력 방식이나 이름을 변경하지 않는다.

## 상태 계약

```tsx
"use client";

import { useState } from "react";
import { AOSTextField } from "@muajigyeong/ui/text-field";
import Switch from "@muajigyeong/ui/switch";

export default function InputExample() {
  const [value, setValue] = useState("");
  const [enabled, setEnabled] = useState(false);
  return <>
    <AOSTextField label="이름" getValue={value} setValue={setValue} />
    <AOSTextField label="비밀번호" type="password" />
    <Switch label="알림 사용" pressed={enabled} setPressed={setEnabled} />
  </>;
}
```

- AOSTextField는 getValue/setValue를 함께 전달해 부모 상태로 제어한다.
  둘 다 생략하면 내부 상태를 사용한다. 네이티브 value/onChange와 혼용하지 않는다.
  검색 화면처럼 value/onChange만 사용하는 기존 방식도 유지하고 별도 검증한다.
  기존 native props 전달 순서는 호환성을 위해 바꾸지 않았다. 떠 있는 라벨의
  채움 상태는 기존처럼 getValue/내부 상태를 기준으로 하므로 새 사용처에는
  getValue/setValue 방식을 권장한다.
- Switch는 pressed와 setPressed를 함께 전달했을 때 부모 제어 모드다.
  onChangeCallback은 사용자 변경에 대해 다음 boolean 값을 한 번 전달한다.
  앱 설정 화면의 기존 방식(setPressed는 no-op, onChangeCallback에서 상태 갱신)도 유지한다.
- Switch의 labelClassName은 바깥 label, className은 input에 적용한다.
- AOSTextField의 className은 기존처럼 바깥 label에 적용한다.
- 명시적 id와 자동 id, label 연결, 마운트 전후 동작을 유지한다.

## 내부 의존성과 스타일

두 컴포넌트가 사용하는 useMount를 UI src/internal/use-mount.ts에 비공개 구현으로
포함했다. 기존 훅의 내용과 주석을 그대로 보존하며 앱의 @/ 경로를 참조하지 않는다.
앱의 useMount는 settings-initializer도 사용하므로 그대로 남긴다.
앱과 UI에 훅 구현이 존재하지만 앱이 UI 내부 파일을 직접 참조하지 않는다.

기본 theme.css에는 --sand-500, --teal-200, --teal-300,
--color-button-accent를 추가한다. 앱의 globals.css와 화면 배치는 변경하지 않는다.
모듈 CSS는 원본과 동일하며, 키보드 포커스·고대비·모션 감소 스타일도 보존한다.

## 검증

UI 저장소에서 실행:

```bash
npm run typecheck
npm run build
npm run test:browser
npm pack
```

브라우저는 최초 `npx playwright install chromium`으로 설치하거나,
PowerShell에서 `$env:PLAYWRIGHT_CHANNEL = 'msedge'`를 지정해 기존 Edge를 사용한다.

이번에 추가하는 검증:

- 텍스트 입력의 내부 상태, 부모 제어, 외부 초기화, 라벨 연결, id 중복 방지.
- 비밀번호 표시/숨김 키보드 조작과 값 유지, disabled/readOnly.
- 스위치 Space 조작, 부모 제어, 외부 갱신, 콜백 횟수, 앱의 콜백 제어 방식.
- 스위치 disabled, 명시적/자동 id, 접근 가능한 이름, 소비자 CSS 클래스.
- 기존 일곱 컴포넌트와 Autodocs 회귀 검증.

앱에서도 타입 검사·빌드·기존 테스트와 로그인 입력/검색/설정 화면을 확인한다.
실제 로그인 요청이나 서버 데이터 변경 없이 임시 브라우저에서 입력과 설정만 조작한다.
