# 공통 UI 2차 분리 — 2026-09-14

## 범위

UI 패키지 0.2.0에 SectionWithHeader, FormActionButtons, StatusToast를 추가했다.
컴포넌트 구현과 CSS, JSDoc, Storybook 예제는 독립 UI 저장소에서 관리한다.
앱에서는 기존 업무 로직과 화면 구조를 유지하고 패키지 하위 경로로 import한다.
기존 소스에 있던 주석은 보존하고, 새 API 설명은 JSDoc으로 추가했다.

| 컴포넌트 | 역할 | 추가하거나 명시한 계약 |
| --- | --- | --- |
| SectionWithHeader | 제목과 본문을 가진 section | 제목 level, 서버 렌더링 가능한 하위 export |
| FormActionButtons | 취소·확인 버튼 묶음 | cancelButtonClassName, confirmButtonClassName |
| StatusToast | 일시적인 결과 알림 | 자체 숨김 텍스트 스타일, className, notificationId |

## 앱 스타일 보존

FormActionButtons 안의 review 전용 전역 클래스는 제거했다.
장소 등록 화면과 리뷰 편집 화면은 버튼별 CSS Module 클래스를 props로 전달한다.
기존 스타일 선언값과 선택자 우선순위를 유지해 모양이 바뀌지 않도록 했다.
confirmBusy는 기존처럼 확인 버튼을 포커스 가능하게 유지하면서 실행만 막는다.
confirmDisabled와 cancelDisabled는 네이티브 disabled를 사용한다.

StatusToast의 기본 위치(left: 48%)와 duration(5000ms), 색상, 알림 역할을 유지했다.
별도 위치 조절은 className으로 전달한다. 토스트를 여러 번 표시하면서 메시지가 같으면
notificationId를 바꾼다. 지정하지 않으면 기존 message/duration 기반 동작을 유지한다.
시각적 표시 종료와 스크린리더의 실제 음성 출력은 별개이며 자동 검증은 DOM 의미와
관련 속성·스타일을 확인한다. 스크린리더 음성 출력 자체를 인증한 것은 아니다.

## 사용 예제

```tsx
import SectionWithHeader from "@muajigyeong/ui/section-with-header";
import FormActionButtons from "@muajigyeong/ui/form-action-buttons";
import StatusToast from "@muajigyeong/ui/status-toast";

<SectionWithHeader level={2} title="설정">본문</SectionWithHeader>

<FormActionButtons
  onCancel={onCancel}
  onConfirm={onSave}
  confirmBusy={isSaving}
  cancelButtonClassName={styles.cancel}
  confirmButtonClassName={styles.confirm}
/>

<StatusToast
  message="저장했습니다"
  announcement="변경한 설정을 저장했습니다"
  notificationId={saveSequence}
/>
```

버튼과 토스트를 사용하는 대화형 예제는 클라이언트 컴포넌트에 둔다.
SectionWithHeader는 서버 컴포넌트에서도 사용할 수 있다. 서버에서 사용할 때는
위의 하위 경로를 사용한다. 패키지 루트 barrel은 기존 client 경계를 유지한다.
패키지 기본 theme.css에 --teal-900을 추가했고 앱의 globals.css는 변경하지 않았다.

## 문서와 검증 명령

UI 저장소:

```bash
npm run typecheck
npm run build
npm run test:browser
npm pack
```

브라우저 검증에는 Playwright Chromium이 필요하다. 최초에 `npx playwright install chromium`을
실행하거나 설치된 Edge를 사용하도록 PowerShell에서 `$env:PLAYWRIGHT_CHANNEL = 'msedge'`를 지정한다.
test:browser는 Storybook을 빌드하고 임시 로컬 서버에서 일곱 컴포넌트를 검사한다.
버튼 busy/disabled, CSS 연결, 제목 계층, 토스트 종료·같은 메시지 재표시,
숨김 알림 스타일, 기존 네 컴포넌트 키보드 동작과 Autodocs를 확인한다.

앱은 새 원격 UI 커밋을 설치하고 타입 검사·프로덕션 빌드를 실행한다.
테스트 스크립트는 UI 저장소에 보관하며 문서 생성 결과와 node_modules는 커밋하지 않는다.

## 검증 결과

- UI 타입 검사, ESM 빌드, tarball 생성 통과.
- Storybook 문서 빌드와 일곱 컴포넌트 브라우저 검증 통과.
- 앱에 0.2.0 tarball을 설치한 상태에서 타입 검사와 프로덕션 빌드 통과.
- 실제 앱 고객센터 제목 계층, 장소 찜 토스트, 리뷰 기간 선택의 초기화·적용 동작 통과.
- 기존 테스트 122개 모두 통과. 실행 명령:
  `node --import tsx --import ./tests/register-server-only.mjs --test tests/*.test.ts`.
- 앱 전역 테마와 업무 로직을 변경하지 않았고 git diff --check 통과.

빌드의 기존 상위 lockfile 경고와 Storybook의 use client/번들 크기 경고는 남아 있다.
새 구현에서 이를 숨기거나 빌드 검증을 생략하지 않았다.
